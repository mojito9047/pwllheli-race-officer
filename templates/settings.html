Wiring notes

Use an opto-isolated relay or proper interface between the serial adapter and the horn circuit. Do not connect a horn directly to a PC serial pin.

For the ProLog-style horn interface, DTR drives the horn relay. RTS is held asserted as the feedback-contact common; the contact returns RTS to DCD when idle and CTS when the horn/manual button is active.

Virtual Race Officer

Natural-language commands from a boat (VRO)

The Virtual Race Officer at /vro lets somebody run racing by typing plain English when there is no race officer in the hut. Who may use it is a per-user permission (VRO in Users above) — no role grants it, administrators included.

Interpreter: {{ assistant_status.text }}

A model is optional. Without one the app uses its own small grammar, which handles status, create a race at 11, add all the boats, use course 4 and shorten at mark 4 — and answers “I did not understand that” to anything else. That is deliberate as a fallback: it is what still works when the hut can reach nothing. It is not meant to be the everyday interpreter.

The model only ever picks a command and its arguments. The five minutes between the warning signal and the gun, whether a mark is on the course, whether a series exists — all of that is applied afterwards in Python, and nothing happens until the read-back is confirmed. If a model cannot be reached, the grammar answers instead.

Web server

How many people at once, and the address they reach it on

The app serves the race office, the clubhouse display and every competitor's phone from this PC. The first three set how much of that it will take at once. Those three take effect when the app restarts.

Raise the connection limit first if phones on the water get “cannot connect” while the race office is fine. It counts open connections rather than people, and a browser holds several at a time, so the limit is reached long before that many are watching. Worker threads is how many requests are served at once; more costs little, because they are mostly waiting on disk and network. The idle timeout reclaims a connection from a phone that went out of range.

The public address is the one competitors type in. Reached from outside, the app is behind the relay and only ever sees the tunnel's own internal hostname, so any address it builds for the outside world names a machine nobody can reach. Today that is the logo addresses the live stream fetches; set this and they point at the club instead. Leave it empty on the hut network, where the address a request arrives on is already the right one. Scheme and host only, no trailing path. Unlike the three above, this takes effect immediately.

GPS tracking & automated finishes

Boat trackers via Traccar; RO-confirmed GPS finishes

Boats carry Queclink trackers that report to a Traccar server on the relay. The hut app pulls positions from Traccar (outbound — no open port on the hut), shows the fleet live on the race course chart, and can detect finish-line crossings. Turn on the simulator to preview the map and auto-finish without any hardware.

{# On its own row rather than a fourth in the grid above. Those tracks cannot shrink below their text, so a fourth entry crowds the row and pushes it past the edge — and this one has an explanation to sit with, which the others do not. #}

Asks each racing GL521MG for its position every 20 s, from the warning signal to a minute after it finishes, instead of waiting up to 45 s for its own report. Costs about 1%/h of that tracker's battery. Other models are unaffected — see Yacht tracking.

Within the radius a boat counts as having rounded whichever way it passed. Beyond it, the gate reach is how far off it may pass on the hand the course requires and still count. A third test needs no setting. See Yacht tracking for how they work together.

Where it goes

The account ID and keys are the ones in Video & camera — there is only one set to look after. The bucket must be a different one: the video bucket is served publicly, and a backup contains every user account and password hash in the club. Create a second R2 bucket with no public access and name it here.

Older archives beyond that count are deleted after each successful upload, newest kept.

Passphrase

The archive is AES-256 encrypted before it leaves the hut. Record this passphrase in the club password manager, next to the admin login. Nothing — not this app, not Cloudflare, not us — can open an off-site backup without it. Leaving the field blank keeps the saved passphrase. Changing it does not re-encrypt archives already uploaded, so keep the old one until they have aged out.

Any AES-ZIP tool opens these: 7-Zip or WinRAR will extract the data/ folder given the passphrase, with no need for this app at all.

When it runs, and what it includes

Backups are held back while boats are racing, in the three hours before a start, and while race videos are still uploading — the hut is on 4G and a backup must never be the reason a start video is lost. A held-back backup tries again shortly afterwards, and one missed because the PC was switched off is taken when it next starts.
